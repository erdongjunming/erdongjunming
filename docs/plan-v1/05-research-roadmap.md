# 研究与扩展路线

## 1. 当前工程与研究的关系

最小平台回答“动作是否真实执行、记录是否可回放、判断是否独立、模型能否替换”。世界模型研究回答“学到的后果预测能否提升规划成功率或降低总体成本”。前者通过并不能推出后者。

底层抽象围绕可观察状态、动作和目标组织，保留表征学习与规划方向。第一阶段显式寄存器状态已完整可见，无需人为把它包装成四维空间。

## 2. 研究阶段的确定交付

| 顺序 | 交付 | 进入下一项的依据 |
|---|---|---|
| R1 | 冻结转移数据、按轨迹分组、去重与数据摘要 | 数据可重现，泄漏检查通过 |
| R2 | 身份预测、表格/缓存、精确规则对照 | 预测指标与拒绝覆盖率可复核 |
| R3 | 小型监督预测，必要时潜在表示 | 验证集上确有非平凡预测问题，预算允许 |
| R4 | 短视野闭环规划对照 | 精确事实/独立验收保持，误差有界报告 |
| R5 | 增益、负结果、边界、泛化报告 | 判断继续、缩小或结束该研究问题 |

学习模型单步完整状态准确率 95% 可以作为临时观察点，不作为通用安全标准或成功保证。即使达到 99%，长计划仍可能因错误累积失败；必须报告多步与真实任务成功率。

## 3. 净收益判据

实验前写明主指标，避免实验后挑好看的指标。建议主问题为：在相同动作与总查询预算下，学习辅助是否提高 restricted 任务成功率；或在预先规定的成功率容忍范围内，是否降低精确查询次数/实际延迟。

阈值、样本数与置信方法在实验配置冻结，而不是根据首次结果修改。成本同时列出训练、推理、数据采集；只降低 Runtime 查询而增加大量慢预测，不自动构成净收益。

至少对照随机、启发式、精确搜索、缓存；有云端模型时加入 LLM 候选生成。该小世界真实执行很便宜，精确规则很可能更优，这个结果应保留。

## 4. JEPA 或潜在表示的单独提案

只有 R2/R3 表明表示瓶颈后，另写范围有限的实验规格：观测编码、动作编码、预测目标、目标编码器更新、损失与坍塌诊断、同算力基线、评测预算。

不预定某个论文架构必然适合程序语义。程序状态有精确离散约束，压缩表示可能丢掉目标判断所需信息；终验仍走精确状态和执行。

持续学习先采用离线数据追加、版本化训练、保留集回归测试和可回退模型工件。离线重新训练自己的模型不等于改变云端 LLM 权重。

## 5. 真实代码试点的启动条件

需要新设计与大版本契约：不能把文件路径塞进 reg4.State 的 registers。可以复用命令去重、候选协议思想、报告和审计流程，但新环境必须有自己的 State/Action/Observation 及恢复边界。

最窄试点：可信项目的单个 Python 文件、受限文本补丁、固定 pytest 命令、明确文件白名单；测试与验证材料位于 agent 不可写区域。预测先针对测试通过/错误类别，不预测整个操作系统。

需要先完成：隔离后端选择与威胁模型、文件系统越界测试、进程/时间/内存限制、网络策略、测试防篡改、文件快照完整性和副作用恢复说明。临时目录不是沙箱；容器也不保证绝对隔离。

如果开始执行不可信模型生成代码，建议用隔离 VM/经验证的沙箱后端；不能用当前寄存器执行器的安全边界覆盖这类任务。

## 6. 底层优化与平台扩展

| 观察到的事实 | 可评估动作 |
|---|---|
| Python 转移/序列化在 profile 中占主要耗时 | 局部优化或 Rust 扩展，公共数据协议保持版本化 |
| 状态复制占主要成本 | 增量/内容寻址快照，再验证分支隔离 |
| 多机执行成为真实需求 | 新 transport 层与服务 API，不直接散拆已有模块 |
| 外部客户端需要工具互操作 | 在内部端口稳定后添加 MCP adapter |
| GPU 推理是实际瓶颈 | 依据所选模型、实测显存与依赖兼容性优化 |

每项新能力单独立项，给自己的模块卡与契约测试。不因“AI 原生”名称提前做操作系统替换。

## 7. 停止或调整条件

数据或验证器无法信任，先停研究、修工程。多次冻结实验无法超过简单基线，暂停扩大网络，检查任务是否真的需要预测。真实代码风险超出隔离能力，先缩小动作范围。目标变化时保留旧版本与结论，不能覆盖负结果。
