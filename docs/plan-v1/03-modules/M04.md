# M04：SQLite 事务、去重、快照与分支

前置：M02 合并；可在 M01 后用假 Runtime 开工。门槛：G1。权重：5。输入：Task、Command、Snapshot 标识；输出：Observation、StepReceipt、RunExport 与预算。

## 文件与接口

拥有 `src/world_model_lab/storage/{__init__,sqlite_store,migrations}.py`、`tests/storage/`。入口 `SQLiteStore(db_path: str)`，完整实现 StorePort。

数据库 schema 初版 migration=1；SQLite foreign_keys=ON、WAL、有界 busy_timeout。`BEGIN IMMEDIATE` 覆盖去重、版本和预算检查到事实提交。v1 单机写入，不承诺分布式 exactly-once。

## 制作步骤

- [ ] 创建表和唯一键：(run_id,command_id)、(run_id,branch_id)、(run_id,snapshot_id)。完整 JSON、摘要和必要索引并存；每个连接有明确关闭路径。
- [ ] 写 create_run/observe 与输入、出参深复制测试；同 run 重建返回 run_exists。
- [ ] 实现 execute 的事务顺序；用计数 FakeRuntime 证明重复 key 不调用第二次，改变 payload 抛 PortError(idempotency_conflict)。
- [ ] 固定 applied/invalid/rejected 三种 Receipt 的 revision 与预算语义；invalid 也持久化、不回退。
- [ ] 实现 create_snapshot/fork，不覆盖原分支；关联来源 snapshot 和 run。快照/分支上限分别为 64/16，跨 run 引用拒绝。
- [ ] 实现 usage/remaining/reserve_budget。count 必须为正整数；普通预留超预算返回 false、不增加；proposal_count 超预算特例扣到上限、返回 false。exact_queries+model_queries 共用 max_plan_evaluations。
- [ ] 实现 record_control/export_run；控制类型只允许 Schema 列表，导出 Command/Receipt 按一一对应关系保存，摘要可重复计算。
- [ ] 实现 finish_run 和 final_summary、预算事件导出。结束后拒绝新写，允许原命令重试读取；同摘要重复结束不新增事件。
- [ ] 加事务异常、重启、两个连接竞争与响应丢失测试；异常不得留半条记录。

## 核心测试示例

```python
def test_same_command_once(store, runtime, command):
    first = store.execute(command, runtime)
    repeated = store.execute(command, runtime)
    assert repeated == first
    assert store.usage(command["run_id"])["action_attempts"] == 1
    assert store.observe(command["run_id"], command["branch_id"])["revision"] == 1
```

fixture 使用临时 DB、golden.task 和 command 样例；另测试关闭后重新打开 DB 仍返回相同 Receipt。两个连接以相同 expected_revision 发不同新命令，只能一个消费尝试，另一个 state_conflict。

## 故障与恢复验收

S01-S05 全部通过；fork 后修改 child 不影响 parent/snapshot。20 次动作尝试后从初始快照 fork，剩余仍是 0。提交前故障无状态改变；提交后模拟响应丢失，重试得到原记录。

预算在 run 重启后保持已消耗值。恢复只重开数据库并查询，不自动重复未完成的 provider 请求。数据库完整性失败必须报 storage_error，不能自动删库重建。
