# M00：工程底座与集成负责人

前置：无。门槛：G0；持续负责 G1 至 G4 的组合验收。权重：1。输入：完整计划包；输出：可安装、可检查的空仓库与集成流程。

## 文件与接口

拥有 `pyproject.toml`、`.gitignore`、`README.md`、`scripts/`、`tests/integration/`、`.github/`。实际应用根目录检查后确定；不覆盖现有项目，不直接安装到全局 Python。

Python 首期 `>=3.14,<3.15`，运行依赖为空，dev extra 为 pytest、jsonschema、mypy。研究依赖另环境；如依赖不支持 3.14，以实际失败为依据发变更单统一改版本。

创建 src 布局包 `world_model_lab`，打包用 setuptools。M00 管理根 `src/world_model_lab/__init__.py`，该文件只放版本；已列入所有权清单。M10 以后负责 `__main__.py`。

## 制作步骤

- [ ] 检查 D 盘项目路径、Python/Git 实际可调用性，记录路径。初始化 Git 和独立 `.venv`，记录当前分支；当前没有代码无需建历史 worktree。
- [ ] 建立 src/ 测试布局、pytest testpaths、严格 mypy 配置、dev extra。锁定首次安装的准确依赖版本至 `scripts/dev-requirements.lock.txt`，后续所有工作树复用。
- [ ] `scripts/check.ps1` 按顺序调用契约、模块、mypy 和 integration；任何命令退出非 0 时立即退出，保留原退出码。不得依赖 shell 的自动“最后一个成功命令”掩盖前面的失败。
- [ ] `scripts/check_ownership.py` 对 git diff 核查路径与模块清单；`scripts/check_imports.py` 用 AST 检查模块 import 边界。
- [ ] 建 `tests/integration/test_ports.py` 的端口装配；初始只验证空架子可安装，未实现的集成测试必须明确 pending，不用永远通过的假测试。
- [ ] 复制计划与 manifest 到 `docs/plan-v1/`，在 `README.md` 写入口；提交 bootstrap，通知 M01 基准提交。

首次环境命令（仅在实施时执行）：

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -e '.[dev]'

```

每个动作分成准备、执行、核对输出、提交四步，不在一个脚本里覆盖旧目录。
