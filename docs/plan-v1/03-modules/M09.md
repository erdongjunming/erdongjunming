# M09：批量评测、回放与公平对照

前置：M05/M07。门槛：G2，研究阶段复用到 G4。权重：3。输入：RunConfig 列表、RunExport、RunSummary；输出：结构化结果和可追溯报告。

## 文件与接口

拥有 `src/world_model_lab/evaluation/{__init__,runner,replay,reporting}.py`、`tests/evaluation/`。入口：

```python
EvaluationRunner(orchestrators: dict[str, OrchestratorPort],
                 runtime: RuntimePort, verifier: VerifierPort)
```

实现 EvaluationPort；evaluate 按 config.planner_name 选择注入的 orchestrator。每项有新 run_id，各方法互不共享数据库运行预算；顺序执行，避免并发干扰延迟比较。

## 制作步骤

- [ ] validate RunConfig，按顺序评测；一个失败 run 留下失败摘要后继续，严重数据库错误停止且保留已完成条目。不隐瞒失败任务。
- [ ] 用 smoke30 确认 pipeline，再冻结 dev100；random/heuristic/exact_search 使用同 Task、attempts/decisions/plan_evaluations 和 seed。时间、API 的不同成本另列，不把不同单位硬加为一个分数。
- [ ] 从 RunExport 重建分支出生状态，按事件与命令序列核查 Snapshot、revision、去重与 run 总预算；对已提交动作重新调用纯 Runtime 并独立审计。拒绝事件不能推进状态。
- [ ] 检查 exports 的 Command/Receipt 一一对应，attempt_index 连续、command_id 唯一、state_id 与内容相符。篡改一个寄存器/错误 disposition/预算计数要能被发现。
- [ ] 核对 budget_events 的累加与 budget/final_summary 一致；final_summary=null 表示未结束，不把中途数据当成成功 run。按各分支 revision 重建观察，并核对 snapshot 保存的确切 revision。
- [ ] 将 final_observation 对应到实际分支末态，重新独立 check，核对 final_verification；某个其他分支成功不能替代当前结果。
- [ ] write_report 产出 `summary.json`、`runs.jsonl`、`report.md`。按 family/难度分层列成功率、动作数、invalid/rejected、查询数、wall_ms 中位数/P95、tokens/金额已知和未知数量。
- [ ] 保存来源：代码提交、契约摘要、任务摘要、模型/后端、种子、脱敏配置摘要、训练数据版本（若有）。无提交时标 uncommitted，不能标正式可复现发布。
- [ ] 同配置两轮比较语义轨迹；不要比较新的 run_id、UTC 或 wall_ms 字节完全一致。外部模型只承诺请求/响应可追溯，不保证云端输出可复现。

## 核心验收

```python
def test_tampered_receipt_fails_replay(evaluation, exported):
    import copy
    broken = copy.deepcopy(exported)
    broken["receipts"][0]["after"]["state"]["registers"][0] = -8
    assert evaluation.replay(broken)["valid"] is False
```

100 个任务报告分母包含所有启动任务；不以“成功输出 JSON 的次数”为任务成功率。没有 API 调用的离线方法 tokens/cost 为 0；确有调用但缺用量为 null。
