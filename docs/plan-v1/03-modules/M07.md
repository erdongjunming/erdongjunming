# M07：编排、可信计量与最小执行闭环

前置：M03/M04/M06。门槛：G2。权重：5。输入：RunConfig 与注入端口；输出：RunSummary、持久化事实与决策事件。

## 文件与接口

拥有 `src/world_model_lab/orchestration/{__init__,runner,metering}.py`、`tests/orchestration/`。入口：

```python
RunOrchestrator(runtime: RuntimePort, verifier: VerifierPort,
                store: StorePort, decision_factory: DecisionFactoryPort,
                provenance: Provenance, world_model: WorldModelPort | None = None)
```

实现 OrchestratorPort.run；工厂由组合根注入，每个 run 新建。metering 实现 RuntimePort/WorldModelPort 包装器，绑定 run_id、Store 预算；传给候选生成器，真实 execute 仍使用原始 Runtime。

## 制作步骤

- [ ] 在 create_run 后用 Verifier 检查初态，已成功则零动作结束；失败进入循环。run_timeout 使用 monotonic，不能用系统时间差。
- [ ] 每轮读取 Observation/remaining，先预留一次决策预算，然后创建中立 DecisionRequest；history 只含 active branch 及其祖先至快照点的已提交 Receipt，最多 run 的 20 次动作，不包含其他试验分支未来。
- [ ] factory.build(config, metered_runtime, metered_world_model) 使用计量包装器；RunConfig 同时传给适配器工厂约束实际 HTTP 调用。精确与模型查询共用规划预算。请求结束后读取 DecisionPort.usage 并记录 provider_usage 控制事件；假文本不作为用量证据。
- [ ] 在受限响应中先读取 candidates 列表长度并计入候选预算，再 validate_decision、校验 request_id；超预算按契约整批拒绝。结构错误即 provider_protocol，不执行其中任何候选；任务禁用但结构合法的候选可以逐项丢弃。完整原响应长度/结构在 adapter 检查，进入此层时仍防御性验证。
- [ ] decide 抛出 PortError 时仍在 finally 读取该 request 的 usage，持久化实际/未知消耗。Store.execute 的 idempotency_conflict、run_closed、storage_error 属于技术故障，记录并终止，不把它们当作正常动作失败继续循环。
- [ ] 按顺序选择合法候选，记录预测与选择原因，自己产生 Command，执行首个动作。非法候选记为丢弃并消耗提案预算；没有合法候选时进入下一轮，受决策预算限制。
- [ ] 将 Receipt 转成 TransitionResult，由独立 verifier.audit_transition 检查；rejected 不假作执行审计，分别处理 state_conflict/budget 等情况。审计失败即 audit_failed；applied/invalid 后再 check 真实目标。
- [ ] 实现 terminal 优先级：audit_failed → 本轮真实检查 success → 时间/预算 exhausted → provider_error → stop/无进展 failed。已达到目标的最后一次动作允许成功，即使刚好用完动作预算。
- [ ] 汇总 metrics/provenance，调用 Store.finish_run 原子结束并保存摘要。Ctrl+C/取消也以 cancelled 摘要结束；重启只读取历史，不默认重放外部调用。失败也返回最终 VerificationResult。

## 核心验收

```python
def test_predicted_success_is_not_real_success(orchestrator_with_wrong_prediction, config):
    result = orchestrator_with_wrong_prediction.run(config)
    assert result["status"] != "success"
    assert result["final_verification"]["success"] is False
```

此固定 fake planner 提出 ADD(0,0)，却预测 swap-demo 已完成；最终真实状态仍 [1,2,3,4]。另测一直返回非法候选时在 max_decisions/max_proposals 内停止；精确查询和学习查询总数不得超过 max_plan_evaluations。

## 费用与超时边界

max_provider_calls 由 adapter factory 的 transport 包装器逐次 HTTP 尝试检查，重试也计数。设置 max_api_cost 时必须有可信价格配置和每请求输出上限，调用前用上界估价预留额度；无法上界估价时拒绝收费运行，允许 max_api_cost=null 的受限人工配置冒烟测试，并明确未知金额。

同步 HTTP 超时仅确认客户端等待结束，不能保证云端没有完成推理或计费。非取消的本地函数超时在 v1 通过每次查询/展开检查 deadline；任意用户代码执行不在本阶段。
