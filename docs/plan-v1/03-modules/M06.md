# M06：离线候选生成与精确规划基线

前置：M02/M03。门槛：G2。权重：3。输入：DecisionRequest、计量后的 Runtime/WorldModel 端口；输出：Decision，不执行真实命令。

## 文件与接口

拥有 `src/world_model_lab/planning/{__init__,random_policy,heuristic,exact_search,factories}.py`、`tests/planning/`。三个类实现 DecisionPort，usage 返回 None。

入口与构造：`RandomPlanner()`、`HeuristicPlanner(verifier: VerifierPort)`、`ExactSearchPlanner(runtime: RuntimePort, verifier: VerifierPort)`。factory 类实现 `DecisionFactoryPort.build(config, runtime, world_model)`；每次 build 返回新 planner，不跨 run 共用随机状态和搜索缓存。离线工厂不因 RunConfig 存在而发起 provider 请求。

## 制作步骤

- [ ] 固定 Action 枚举：按 SET/ADD/COPY/SWAP 顺序，再索引与参数升序；任务只保留 allowed_ops。列表数量固定（SET68、ADD20、COPY16、SWAP16），同索引和 no-op 允许，搜索可识别等状态并跳过展开。
- [ ] Random 使用 Task.seed 初始化自己的 PRNG，逐轮从合法列表选一个；同任务同决策历史得到同动作序列。
- [ ] Heuristic 优先未满足目标中索引最小的一项，SET 可用时直接目标值；ADD 可用时使用差值截断到 [-2,2]；COPY/SWAP 遍历后用最终目标与 preserve 距离评分，只接受严格改进的首个动作。无法改进返回 stop，不伪称无解。
- [ ] ExactSearch 使用 BFS、完整 State 键、父节点链，深度上限为当前 remaining.attempts，扩展调用都经过传入 Runtime；达到包装器预算上限停止，不越预算继续计算。
- [ ] 所有方法在真实目标已满足时返回 stop；Candidate 的预测根据来源分别标 none/exact，填 full prediction 时长度匹配。每轮至多一个候选，精确搜索保留完整计划用于分析。
- [ ] planner 不读取 Store、Task 私有生成路径，也不发外部请求。若包装器抛 budget_exhausted，返回 error 的结构化结果。

## 核心验收

```python
def test_restricted_add_needs_multiple_steps(exact_planner, request):
    decision = exact_planner.decide(request)
    assert decision["status"] == "candidates"
    assert len(decision["candidates"][0]["actions"]) == 3
    assert all(a["op"] == "ADD" for a in decision["candidates"][0]["actions"])
```

request 使用初值全零、r0 目标 5、preserve[1,2,3]、只允许 ADD 的固定任务；0→2→4→5 是一条合法解，不能将它硬编码成所有任务的算法。

测试搜索预算=1 时返回有界失败；goal 在初态满足时零动作；目标不可达的受限集合不会无限循环。随机策略可以失败，验收要求其行为与计量正确，不要求 100% 成功。
